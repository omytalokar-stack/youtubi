# Dimag AI V2

A standalone, multi-channel YouTube Shorts studio. The React app is in `frontend/`; the Node.js 22 API and automation worker are in `backend/`.

## Local setup

1. Copy `backend/.env.example` to `backend/.env` and configure a reachable MongoDB URI, Google OAuth, Gemini, and a 32-byte `TOKEN_ENCRYPTION_KEY` (64 hex characters or base64). Set `OAUTH_STATE_SECRET` and `CRON_SECRET` to independent, high-entropy secrets. The backend refuses temporary database storage so connected-channel credentials survive restarts.
2. In Google Cloud, enable YouTube Data API v3 and YouTube Analytics API v2, configure the OAuth consent screen and the redirect URI exactly as `OAUTH_REDIRECT_URI`, and use all scopes in the example, including `youtube.force-ssl` for private/unlisted video metadata and publishing. Existing connected channels must reconnect and grant the updated scope before OMES can read or update videos.
3. Configure `frontend/.env` from `frontend/.env.example`. Set the backend's `FRONTEND_ORIGIN` and/or `FRONTEND_URL` to comma-separated exact browser origins (for example, `https://your-project.vercel.app,http://localhost:5173`); the deployed `https://frontend-mu-blush-93.vercel.app` origin is always allowed. Set `PUBLIC_APP_URL` to the deployed frontend URL. Production frontend API requests use the same-origin Vercel rewrite in `frontend/vercel.json`; local development can set `VITE_API_URL` to the backend API. The Google OAuth redirect URI must remain the backend's `/api/youtube/oauth2callback` URL.
4. Install dependencies in the root, `backend/`, and `frontend/` using `npm install`, then run `npm run dev` from this directory.
5. Install FFmpeg and ffprobe on the backend host. The renderer defaults to the `ffmpeg` executable and needs FFmpeg's `libx264`, AAC, FreeType drawtext, crop/scale, and zoompan filters. Optional Pexels or Pixabay API keys enable licensed portrait stock images; bundled Noto Sans Devanagari keeps Latin and Hindi captions available without host font setup.

Gemini generates a 55–70 word script in five 11–14 word sentences, a mid-action hook, a final sentence designed to loop into the opening, and five sentence-aligned visual prompts with distinct topic-specific search queries. The prompt includes the selected channel's 30 most recent topics/titles/hooks as a strict do-not-repeat list. Server validation rejects weak opening phrases, structurally invalid scripts, repeated/near-repeated topics, and duplicate or misaligned scene queries; Gemini gets at most five corrections before the job fails. These checks reduce repetition but cannot guarantee a particular retention rate or a platform moderation outcome.

When `PEXELS_API_KEY` or `PIXABAY_API_KEY` is configured, the backend searches for portrait still images using each scene's own visual query. Downloads are limited to 1 MiB per image and 5 MiB per Short; distinct media IDs/URLs are tracked against the current video and that channel's 30 latest video logs. Missing images and provider errors use each scene's local visual; after a rate limit, already fetched imagery is reused with a different pan/zoom when available. FFmpeg gives each scene a gentle alternating Ken Burns move, encodes scene clips sequentially, then concatenates them with the concat demuxer using stream copy. The final 720×1280, 24 fps video receives timed 3–5-word burned-in captions and Gemini narration using single-threaded `libx264` ultrafast/CRF 26/yuv420p encoding. A render error stops publishing rather than substituting an empty output.

## Automation

Set each channel's independent daily upload time in Settings. The backend also performs a scheduler check every 10 seconds, so a missed external cron hit is recovered automatically while MongoDB and the API remain available. A scheduled run is eligible from its configured IST time through the rest of that IST day, so a temporary restart or a missed 25-minute window does not lose that day's run. Queued or interrupted runs are persisted in MongoDB and recovered by the next worker check, including after a restart. Temporary provider failures stay queued and retry with an increasing delay (capped at one hour); non-transient failures are recorded and are not repeatedly retried throughout the day. Configure cron-job.org as a backup or for explicit external triggering: use `Asia/Kolkata` and send a daily `GET` (or `POST`) request to `https://youtubi.onrender.com/api/automation/trigger` at the same IST time; if channels use different times, create a daily cron job for each time using the same URL. Set the `x-cron-secret: <CRON_SECRET>` header when the backend secret is configured. Before returning `202 Accepted`, the endpoint stores the due-channel queue in MongoDB; uploads then run sequentially. Per-channel status, skip reason, failure stage, and error survive restarts and are returned by `GET /api/automation/status/:channelId`. Normal channels run the native Gemini, voiceover, FFmpeg and YouTube upload pipeline. If OMES is enabled for a channel, it replaces that channel's generation/upload pipeline: daily mode runs at its own IST time, while alternate mode also requires at least 44 hours since the last OMES run.

OMES is intended for completed videos uploaded manually as Private or Unlisted. It uses the channel's uploads playlist, studies recent titles/tags and performance, applies the saved title suffix/core tags/description footer, then makes the latest video Public. Before generating metadata, OMES downloads a serving owner caption track when available and analyzes it with the video's best available thumbnail; captions that are still syncing are skipped. The generated main title is checked against the previous 25 uploads (ignoring the configured suffix) and retried up to twice if it matches or heavily overlaps a recent title. Thumbnail analysis does not inspect the full video frames. **Enabling OMES does not generate or upload Shorts; running it explicitly publishes that latest upload publicly.** YouTube Studio drafts may not yet be accessible through the uploads playlist. The Settings card verifies `CRON_SECRET` once, then the backend issues a 30-day HttpOnly session cookie for saving OMES settings, loading private history, and manual runs. The secret is cleared from the page after unlock; only the signed HttpOnly cookie remains in the browser, inaccessible to frontend JavaScript. The secret is never stored in local/session storage or embedded in the frontend bundle. The cookie is restricted to the configured frontend origin; changing `CRON_SECRET` invalidates existing sessions. Reconnect any older channel that lacks the new video-editing OAuth scope.

OMES browser access uses `POST`, `GET`, and `DELETE /api/channels/omes/session` to unlock, check, and clear the protected 30-day session. The channel-scoped `PUT /api/channels/:channelId/omes`, `POST /api/channels/:channelId/omes/run`, and `GET /api/channels/:channelId/omes/history` routes accept either the protected browser session or the `x-cron-secret` header for server-to-server use.

Manual `POST /api/automation/publish/:channelId` requests remain `202 Accepted` while the normal pipeline runs in the background; the worker refuses to generate/upload when that channel has OMES enabled.

The API limits other requests to 600 per client IP per 15 minutes. Health checks, cron-protected automation triggers, and `GET /api/youtube/channels` are exempt. The frontend coalesces duplicate channel-list requests, caches successful results for 30 seconds, and applies exponential backoff starting at 30 seconds after a 429 while retaining the last known list.

`POST /api/automation/audit-analytics` is protected by the same secret and requires `{ "channelId": "..." }`. The dashboard's manual audit asks for that secret at run time; it is not embedded in the frontend bundle.

`GET /api/analytics/:channelId` syncs channel totals and recent-video statistics from YouTube and stores them against that channel's profile and video logs. `POST /api/analytics/:channelId/audit` refreshes those statistics before running the protected learning audit. The Agent Brain listens for pipeline status events and polls `GET /api/automation/status/:channelId` every five seconds only while that channel is active.

Before each Short, the backend fetches up to 30 recent channel videos, classifies relative winners and underperformers using view/impression velocity, CTR, retention, average view duration, and likes, then saves the performance scorecard and learned formulas/guardrails to that channel's Agent Brain. This requires the YouTube Analytics read-only scope; unavailable analytics metrics are logged and left as zero rather than fabricated. Manual publishing uses the selected channel's saved privacy setting. Review that channel's blueprint and upload visibility before publishing.

## Resource and data boundaries

- Channel-specific reads and writes use `channelId`; scripts load only that channel's profile, brain memory, and 30 latest video topics/titles/hooks/scripts. Each channel stores its own enabled state, IST upload time, last successful auto-publish date, and IDs of previously selected stock images.
- OMES settings and run state are per channel. Video history and OMES audit records are pruned from MongoDB to at most 50 records per channel per collection, 45 days, and 300 total log documents; this cleanup only deletes database logs, never YouTube videos.
- A MongoDB global render lock serializes generation and uploads across channels.
- Use a persistent MongoDB service such as Atlas for local and Render deployments. Render's ephemeral filesystem is not a database; check the Atlas network access allowlist if the backend cannot connect.
- All intermediate voice, scene, subtitle, and render files are created in a unique directory under the operating system's temporary directory. Scene/audio inputs are removed in render `finally` blocks, partial outputs are removed on failure, and the full job directory is removed after upload.
- FFmpeg renders five 6-second portrait scenes sequentially at 720×1280 and 24 fps, using one thread, the `libx264` `ultrafast` preset, CRF 26, and yuv420p. The five encoded segments are concatenated with `-c copy` before the final narration/subtitle pass, so scene streams are not held concurrently. Each render command has an eight-minute timeout. A global render lock has a 15-minute TTL and a one-minute heartbeat; loss of the lock aborts the active FFmpeg process.
- Captions use the bundled Noto Sans Devanagari font through FFmpeg drawtext, with 48px white text, a translucent dark box, dark outline/shadow, and dynamic 3–5-word timed groups. Downloaded images are limited to 1 MiB each and 5 MiB total per job. Scene images, intermediate clips, manifests, audio, and the final MP4 are removed during render/upload cleanup.
- YouTube refresh tokens are encrypted with AES-256-GCM. Keep environment files and secrets out of source control.
